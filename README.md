# PostgreSQL → S3 backup service

Автономный Docker-сервис резервных копий PostgreSQL. Не зависит от backend
или FastAPI. Версия разработки 0.1.0. Репозиторий: https://github.com/boradydev/postgres_s3_backup.
Использует штатные pg_dump/pg_restore и AWS boto3; наша обвязка — расписание,
догоняющий запуск, readback SHA-256, состояние и ротация по количеству.

## Настройки

Настройки передаются переменными окружения. Образ сам не читает `.env`:
для Docker используйте `--env-file .env`, для Compose — `env_file`.
Скопируйте `.env.example` в `.env` и заполните обязательные подключения.
`.env` исключён из Git. Не публикуйте реальные ключи и пароли.

### Обязательные подключения

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_HOST` | Имя контейнера или адрес PostgreSQL, доступный из контейнера бэкапов |
| `POSTGRES_DB` | Имя одной копируемой базы; латинские буквы, цифры, подчёркивание |
| `POSTGRES_USER` | Пользователь PostgreSQL с правами чтения копируемой базы |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `BACKUP_S3_ENDPOINT` | HTTPS endpoint S3-совместимого хранилища |
| `BACKUP_S3_BUCKET` | Имя существующего бакета |
| `AWS_ACCESS_KEY_ID` | Ключ S3 с правами list/get/put/delete в выделенном префиксе |
| `AWS_SECRET_ACCESS_KEY` | Секретный ключ S3 |

Отсутствующая или пустая обязательная переменная останавливает запуск.
Для временных S3-ключей SDK также поддерживает необязательный `AWS_SESSION_TOKEN`.

### Необязательные настройки

Если переменная не передана, используется значение из таблицы. Переданное
некорректное значение вызывает ошибку настройки; пустая строка не означает
«использовать значение по умолчанию».

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `POSTGRES_PORT` | `5432` | Порт PostgreSQL, целое число 1–65535 |
| `BACKUP_S3_REGION` | `ru-1` | Регион для подписи S3-запросов; для другого провайдера укажите его регион |
| `BACKUP_S3_PREFIX` | `postgres-backups/production` | Префикс объектов; имя базы добавляется автоматически. Допустимы латинские буквы, цифры, `_`, `-`, `/` |
| `BACKUP_KEEP` | `30` | Сколько успешных копий категории `daily` хранить |
| `BACKUP_MANUAL_KEEP` | `30` | Сколько успешных копий категории `manual` хранить |
| `BACKUP_PREDEPLOY_KEEP` | `30` | Сколько успешных копий категории `predeploy` хранить |
| `BACKUP_TIME` | `17:00` | Ежедневное время запуска в формате HH:MM, 00:00–23:59 |
| `BACKUP_TIMEZONE` | `Europe/Moscow` | Часовой пояс IANA, например `UTC` |
| `BACKUP_DUMP_TIMEOUT` | `1800` | Максимальное время выполнения `pg_dump`, секунды; не общий лимит загрузки в S3 |
| `BACKUP_RETRY_INTERVAL` | `300` | Ожидание после неудачной попытки в режиме `serve`, секунды |
| `BACKUP_POLL_INTERVAL` | `60` | Интервал проверки расписания и повторной очистки в режиме `serve`, секунды |
| `BACKUP_STATE_DIR` | `/state` | Каталог состояния, блокировки и временного дампа; должен быть постоянным и доступным для записи |
| `BACKUP_ALLOW_HTTP` | `0` | Только `1` разрешает HTTP endpoint для локального тестового S3. Для настоящего хранилища оставьте HTTPS |

Лимиты копий, таймаут и интервалы — положительные целые числа; `0` не означает
бесконечное хранение или отключение. Интервал проверки может задержать запуск
после заданного времени максимум примерно на этот интервал, если сервис свободен.
Повтор после ошибки действует только пока контейнер запущен; ручная команда
возвращает ошибку без бесконечного ожидания.

В `/state` монтируется постоянный том. UID/GID контейнера — 10001. Для другой
комбинации endpoint/бакет/префикс используется отдельный том состояния.
Секреты передаются через приватный env_file, не включаются в образ или Git.
Смена настроек требует пересоздания контейнера с новыми переменными.

`POSTGRES_IMAGE` — отдельный аргумент **сборки**, не переменная запущенного сервиса.
По умолчанию Dockerfile использует закреплённый digest `postgres:17-bookworm`.
Для другой версии клиента: `docker build --build-arg POSTGRES_IMAGE=... ...`.

## Команды

- `serve` — расписание и одна догоняющая копия после пропуска.
- `run` или `run --category manual` — дополнительная ручная копия с отдельным лимитом;
  не засчитывается как выполнение ежедневного расписания.
- `run --category daily` — принудительная ежедневная копия сейчас; засчитывается
  за последний наступивший срок расписания.
- `run --category predeploy` — копия перед миграцией с отдельным лимитом.
- `status` — результат и метаданные без секретов.
- `download --manifest <S3-key.json> --output /state/restore.dump` — скачать
  с проверкой SHA-256; существующий файл не перезаписывается.

## Поведение и хранение

При первом запуске `serve` создаётся начальная копия. После пропущенных дней
создаётся одна догоняющая копия за последний наступивший срок, без копий за каждый
пропущенный день. Сохранённое состояние предотвращает дубли при перезапуске.
Ручные и преддеплойные копии не отменяют очередную ежедневную копию.

Категории хранятся в отдельных S3-префиксах `daily/`, `manual/`, `predeploy/`.
При значениях по умолчанию возможно до 90 успешных копий: по 30 каждого вида.
Ротация запускается после успешного бэкапа и проверяет лимиты всех категорий;
просто уменьшение лимита в env не удаляет файлы немедленно. Старые ручные копии,
созданные прежней командой `run` в `daily/`, автоматически не переклассифицируются.
Если осталась незавершённая загрузка, сначала завершается она с прежним ключом.

Весь новый dump читается обратно из S3: учитывать исходящий трафик тарифа.
Manifest публикуется после проверки архива и тоже читается обратно.
Неудачный бэкап не удаляет старые копии. Повтор после сбоя использует
сохранённый архив и тот же ключ. Ночь/выходные без включённого ПК — норма;
uptime-контроля нет. Ошибка очистки не отменяет успешный бэкап.

Начальный образ содержит PostgreSQL client 17; для другой версии сервера
выбирается совместимый POSTGRES_IMAGE и проверяется восстановление.
Дамп одной базы не включает роли и секреты всего кластера. Шифрование самих
файлов не реализовано, транспорт защищён HTTPS. GlitchTip будет подключён
отдельно; пока ошибки доступны в логах/status.

## Разработка

```sh
poetry install --no-root
poetry run python scripts/export_requirements.py
poetry run ruff check src scripts tests
poetry run pyright
docker build --target test -t postgres-s3-backup:test .
docker run --rm postgres-s3-backup:test
docker build --target runtime -t postgres-s3-backup:dev .
```

`tests/smoke.ps1` проверяет dump → S3-эмулятор → скачивание → реальное
восстановление в отдельную тестовую PostgreSQL. Реальные S3-ключи не нужны.

## Публикация Docker-образа

Готовый образ: `ghcr.io/boradydev/postgres_s3_backup:<version>` (`linux/amd64`).
Реальные env-файлы, пароли и S3-ключи при сборке не используются.

Обычные push/PR в `master` выполняют проверки без публикации. Выпуск:

1. Обновить версию в `pyproject.toml`, проверить и отправить изменения в `master`.
2. Создать и отправить тег с той же версией, например `v0.1.0`.
3. Workflow **Publish backup image** проверит версию и принадлежность коммита
   истории `master`, выполнит CI, включая восстановление тестовой базы,
   затем опубликует образ с тегом `0.1.0`. `latest` не публикуется.

Первый выпуск также можно запустить кнопкой **Run workflow** у workflow
**Publish backup image**, выбрав `master`. Используется версия из `pyproject.toml`.
Уже существующая версия повторно не публикуется: нужно увеличить версию.
Обновления образа не перезапускают приложение на VM автоматически.

Авторизация workflow использует встроенный `GITHUB_TOKEN` с `packages: write`.
Отдельные GitHub Secrets для публикации не требуются. После первой публикации
в GitHub откройте пакет → Package settings → Change visibility → Public.
Пакет GHCR изначально приватный даже при публичном репозитории.
Публичный образ скачивается без авторизации:

```sh
docker pull ghcr.io/boradydev/postgres_s3_backup:0.1.0
```

В Docker Compose укажите ту же полную ссылку в `image:`. Для строгой фиксации
можно использовать `image: ghcr.io/boradydev/postgres_s3_backup@sha256:...`:
конкретный digest публикуется в итогах workflow. Постоянный volume `/state`
и env-переменные задаются на сервере как раньше.
